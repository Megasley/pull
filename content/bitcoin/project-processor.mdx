Merchants need idempotent invoices, confirmation policies, and reliable callbacks. This project is the on-chain cousin of a Lightning POS.

Complete **Step 1 // Required reading** in the study plan above, then continue here. This closes **Projects**.

## Step 2 — Goal

API endpoints to:

1. Create invoice (amount, expiry, address)
2. Query invoice status
3. Register webhook URL
4. Mark paid after N confirmations

Return a BIP-21 URI with the invoice details.

## Step 4 — Build & evidence (lab)

Implement against `/projects/payment-processor`. Capture repo link, happy-path demo, and one failure case.

### Common mistakes

- Reusing deposit addresses across invoices
- Firing webhooks twice without idempotency keys
- Treating 0-conf as settled for non-trivial amounts
